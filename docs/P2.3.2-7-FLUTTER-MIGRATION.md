# P2.3.2–P2.3.7 Flutter migration status

This branch is an isolated Flutter implementation track. The existing web POS under `docs/index.html` is intentionally left unchanged.

## Implemented in this branch

- Flutter app shell and responsive navigation.
- Pearl light surfaces and Charcoal Silver dark surfaces.
- Product model, cart-line model, transaction model.
- SQLite schema for products, transactions, and transaction items.
- Product search by name, code, and barcode.
- Manual product create/edit form.
- Camera barcode scanning flow using `mobile_scanner`.
- Cart quantity controls and integer-rupiah subtotal calculations.
- Checkout in a SQLite transaction: validates payment, decrements stock conditionally, and stores transaction/items atomically.
- Recent transaction list and model unit tests.
- CI workflow that generates Android platform scaffolding, runs analysis/tests, and attempts a debug APK build.

## Stage checklist

- P2.3.2 — Flutter foundation: source committed.
- P2.3.3 — Product model/search and manual product entry: source committed; import of legacy product catalog remains outstanding.
- P2.3.4 — Cart, quantity, subtotal, total: source committed.
- P2.3.5 — Cash/non-cash checkout, payment validation, stock decrement, transaction persistence: source committed. QRIS is represented as a non-cash payment method only; this is not a payment-provider integration or payment confirmation.
- P2.3.6 — Barcode camera flow, stock, and recent transaction list: source committed; real device/camera and data migration still need validation.
- P2.3.7 — Theme/responsiveness and regression validation: theme/layout source and automated test/CI definitions committed; do not mark complete until CI and a real Android-device smoke test pass.

## Critical data migration notes

The existing product catalog (previously described as approximately 4,348 products) has not been imported into the Flutter SQLite database yet. The new local database starts empty. Do not use this branch for live cashier transactions until the authoritative product dataset, purchase prices, expiry/batch fields if applicable, existing transaction history, report/export/printing workflows, and QRIS asset/confirmation process are migrated and reconciled.

The legacy web implementation remains available on the default branch. No claim is made that an APK has already been built or tested on a device.
